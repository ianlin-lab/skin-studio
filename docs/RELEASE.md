# Skin Studio 发布、安装与更新

## 0.1.4

适配 ChatGPT 桌面版 26.1013.31256：修复文艺复兴主题的删除确认弹窗对比度，以及 Claude Warm 浅色聊天输入区的边界和可读性；移除会把聊天栏挤出窗口的滚动区毛玻璃样式。切回原生外观改为仅清理当前主题，不再重启 ChatGPT；本机调试会话在 ChatGPT 自然退出前继续待命。增加 GitHub 新版本提示，并为版本标签配置自动测试、打包和上传 DMG。

此版本不迁移或覆盖已保存的主题参数。当前仓库由本地正常 Git 历史维护，个人主题仍保存在用户数据目录，不会提交到 Git。

## 0.1.3

修复 0.1.2 安装后被 macOS 提示“应用已损坏”的打包问题。此前的构建未给应用包生成完整签名；本版使用临时签名，并在发布前校验整个应用包的签名与安装后的启动。功能与主题内容延续 0.1.2。

已安装 0.1.2 且可以正常启动的用户不必清除主题数据；下载 0.1.3 后直接替换应用即可。

## 0.1.2

适配本次验证的 Codex 桌面版 26.911.61220：修复文艺复兴工坊主题的侧边栏文字、聊天输入区对比度，以及输入区附近的浅色空白。新版聊天输入区使用独立表面容器，因此修复同时更新了注入适配规则，不会更改用户保存的主题配色参数。

从 0.1.1 更新时，不必先删除旧版应用或主题数据。先在旧版中恢复 Codex 原生界面并退出 Skin Studio，再将新版应用拖入“应用程序”并选择替换；打开新版后重新应用主题。

## 给使用者

每个正式版本会发布在 GitHub Releases。下载名称中包含 `arm64` 的 DMG，打开后把 `Skin Studio.app` 拖到“应用程序”文件夹。

第一次从此前的开发版切换到正式应用时，Skin Studio 会尝试迁移已保存的主题、素材和当前主题状态；迁移只发生在新的正式数据目录为空时，不会覆盖现有正式版数据。

更新时可在 Skin Studio 左下角点击“检查更新”；发现新版会打开本仓库 GitHub Release 下载页。下载新版本 DMG，用新的 `Skin Studio.app` 覆盖“应用程序”中的旧版本即可。当前没有后台自动安装，不需要账号或云端同步。

当前没有 Apple Developer 签名与公证。macOS 可能提示来自未识别开发者；请在 Finder 中右键 `Skin Studio.app`，选择“打开”，或在“系统设置 → 隐私与安全性”中选择“仍要打开”。不要关闭 macOS 的全局安全设置。

## 给维护者

源码保存在本 GitHub 仓库；DMG 不提交进 Git 历史，而是作为同一仓库 GitHub Release 的附件发布。这样克隆仓库的人得到完整源码，普通使用者只需下载 DMG。

从 0.1.4 起，平时修改源码后先提交并推送 `main`，需要发布时：

1. 确认本地 `main` 已同步、工作目录干净，并且项目依赖已用 `npm ci` 安装。
2. 运行 `npm version patch`。它同时更新版本号、创建版本提交与 `vX.Y.Z` 标签；较大的功能发布可改用 `npm version minor`。
3. 运行 `git push origin main --follow-tags`。GitHub Actions 接到版本标签后自动运行测试、类型检查、Apple Silicon DMG 构建和临时签名校验，全部通过才创建 GitHub Release 并上传安装包。
4. 到仓库的 Actions 与 Releases 页面确认绿色构建和 DMG；首次更新建议自己下载、替换并打开一次。若 Actions 失败，不要把该版本链接发给朋友，先修复再发布新版本号。

目前是临时签名，不是 Apple Developer 正式签名或公证。应用内提示只负责查新版并打开下载页；macOS 可靠的后台自动安装需要正式签名，暂不启用。
